# 全文工作流

先读 [工作流与验收](references/workflow.md)。以当前原题、用户选择及当年官方规范为依据；优秀论文经验不能覆盖硬约束，也不能保证获奖。

1. 盘点现有题面、数据、模型、代码、数值结果与稿件，从缺失环节继续。记录每问要求的输出、条件、单位、附件格式与问题间依赖；不为局部修正重做全题。
2. 先理解和建模、再求解验证；得到可追溯结果后组织正文，最后写摘要。失败验证应返回其根因所在的模型、算法或数据处理处。
3. 按下表读取需要的兄弟技能；它们是工作流能力，不表示另开任务或启用并行代理。兄弟目录未安装时，执行本技能参考文件中的最小闭环，并说明未加载的专项资源，不声称已调用。

|任务|技能|交接物|
|---|---|---|
|压缩题面而保持含义|cumcm-problem-restatement|需求映射与重述|
|解释选型和技术路线|cumcm-problem-analysis|逐问瓶颈、路线、验证计划|
|关系、假设、变量、数学模型|cumcm-modeling|完整可计算模型与成立条件|
|求解器、实现与复现|cumcm-solving|代码输出、参数依据、解的状态|
|检验模型及数值可信度|cumcm-validation|风险对应的实验与证据边界|
|把结果转为答案|cumcm-results|答案、表图与解释|
|优缺点、局限与改进|cumcm-model-evaluation|有证据的能力和适用边界|
|章节措辞和论证衔接|cumcm-writing-style|不改数学含义的精修稿|
|浓缩已完成工作|cumcm-abstract|与正文一致的摘要和关键词|

4. 用“每问答案—模型—证据”组织章节。公共关系只写一次，递进问题写清新增条件；不固定章数、顺序或字数比例。
5. 验收时实际查题目要求是否都有答案，关键数字能否追溯到输出，公式/图表/文献是否可定位，假设是否偷偷削弱约束，结论强度是否超过验证。修改后同步受影响的摘要与结论。

交付现有项目要求的稿件与支撑文件，并列出尚未完成的数学、数据或人工核验事项。缺少数据时可以完成结构与模型，不能编造结果或宣布提交就绪。保留AI实际使用记录，核心内容交队员人工审查；不把内部路径、研究语料作者信息写入参赛稿。
